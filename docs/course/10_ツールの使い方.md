# 第10回　自動検出ツールの使い方

## 今日のゴール

- ツールをセットアップして、自分のウォッチリストで動かせる
- 「どれを・いつ・どの方法で建てて・いつ現渡しするか」をツールに試算させる
- 毎日自動で実行する仕組みを作れる

> ツールの出力は、入力した値と設定にもとづく試算です。特定の銘柄の売買を勧めるものではありません。発注前に証券会社の画面と会社のIRで必ず確認してください。

---

## 1. ツールがやってくれること

| 機能 | コマンド |
|---|---|
| 条件を満たす候補の一覧（見込み利益・どこで・いつクロスするかの目安） | `plan` |
| 資金枠に収まる組み合わせだけを選ぶ | `plan --budget 金額` |
| 今日と次の営業日にやること（エントリー・最終日・短期初日・現渡し）、要対応の建玉 | `today` |
| 建てた建玉の記録（クロス・現渡し・優待の受取） | `position add` / `close` / `received` / `list` |
| ウォッチリストと設定の入力チェック | `check` |
| ウォッチリストの1年分の権利日カレンダー | `calendar` |
| 権利付最終日・権利落ち日・短期初日の計算 | `dates` |
| 1銘柄のコスト試算 | `cost` |
| 確定申告用メモ | `tax` |
| スマホのカレンダーに入れられるファイル（.ics） | `plan -o` |

**ツールがやらないこと**：一般信用の在庫の確認、発注、優待情報の収集。これらは証券会社の画面と会社のIRで行います（ログインが必要・利用規約の制約があるため）。

## 2. セットアップ

リポジトリの [README の「はじめての人の最短手順」](../../README.md) のとおりに進めます。要点は次のとおりです。

- 必要なもの：Python 3.9 以上（追加のライブラリは不要）
- コマンドは README.md があるフォルダで実行する
- この講座の `python -m …` は、**Windows では `py -m …`、Mac では `python3 -m …`** に読み替える

```bash
python -m yutai_cross init        # mydata/ にサンプルをコピー（実績ファイルは見出しだけ）
python -m yutai_cross plan        # サンプル（架空銘柄）で動作確認
```

`mydata/` はあなた専用のフォルダです（git の管理対象外にしてあります）。証券会社からダウンロードした株価の CSV なども、ここに置いてください。

## 3. ウォッチリストを作る（`mydata/watchlist.csv`）

Excel で開いて編集できます。保存するときは「ファイルの種類」を **CSV UTF-8（コンマ区切り）** にして上書きしてください（「CSV（コンマ区切り）」＝Shift_JIS でも読めます）。1行＝1銘柄です。

最低限、**コード・銘柄名・権利月・株価・優待価値・一般信用** の6列を埋めれば動きます。

| 列 | 必須 | 書き方の例 | 説明 |
|---|---|---|---|
| コード | ○ | `7203`、`130A` | 銘柄コード（全角でも可） |
| 銘柄名 | | `○○食品` | |
| 権利月 | ○ | `3`、`3・9` | 複数の月は「・」「;」で区切る。Excel は `3/9` を日付に変えてしまうので「・」がおすすめ |
| 権利日 | | `末`、`20` | 空欄は月末 |
| 必要株数 | | `100` | 空欄は100 |
| 株価 | △ | `1850` | 貸株料の計算に使う。`--prices` で上書き可 |
| 優待内容 | | `QUOカード1000円` | メモ用 |
| 優待価値 | ○ | `1000` | 自分で使う場合の価値（円）。見積もり方は第5回「5. 優待の価値をどう見積もるか」。数字だけ書く（「1,000円」も可） |
| 換金価値 | | `950` | 売った場合の価値（円）。設定 `valuation` を `resale` にするとこちらで判定 |
| 1株配当 | | `20` | その権利日の1株配当（予想）。無配は空欄か `-` |
| 貸借 | | `○` / `×` | 貸借銘柄なら○（制度信用で売れる） |
| 一般信用 | | `SBI短期;楽天短期` | 証券会社の「一般信用売建可能銘柄一覧」で確認して書く。空欄や `○` は「全社・全方法を候補」（在庫が少ない無期限も含む）、`なし` は一般信用不可 |
| 長期条件 | | `1年以上継続保有` | 書くと初期設定では見送り |
| 人気 | | `高` / `中` / `低` | 先回りの度合い（第7回）。空欄なら自動判定（3月・9月の権利、または優待価値÷(株価×必要株数)が1%以上なら高、それ以外は中） |
| 逆日歩想定 | | `2` | 制度信用の逆日歩の見込み（円/株/日）。空欄なら下の見積もりを使う |
| 逆日歩最悪 | | `16` | 逆日歩の見積もり（円/株/日）。空欄なら株価から自動で概算（最高料率×4倍） |
| クロス済 | | `○` | 建てたら○（`position add` で記録する場合は不要）。エントリーと最終日の通知が止まり、現渡しの通知だけ出る。現渡しが終わったら空欄に戻す |
| メモ | | | 自由記入 |
| 有効 | | `○` / `×` | ×にすると一時的に無視 |

「一般信用」列には、証券会社名（`SBI`、`楽天`）、証券会社名＋期限（`SBI短期`、`楽天無期限`、`SBI証券(短期)` なども可）、設定の id（`sbi_short`）が使えます。読めない書き方をすると、注意事項に「〜を読めません」と出ます。

`#` で始まる行はコメントです。エラーのときに表示される行番号は、Excel の行番号と同じです。

書き終えたら `python -m yutai_cross check` で入力チェックをします。読めない行・読めない書き方・売建できない銘柄・株価が空の銘柄を、まとめて「要確認」として表示します。

## 4. 設定（`mydata/settings.json`）

主な項目（全項目の説明はファイル内のコメント参照）：

| 項目 | 初期値 | 意味 |
|---|---|---|
| `valuation` | `benefit` | `benefit`＝優待価値で判定、`resale`＝換金価値で判定 |
| `min_profit_yen` | 300 | これ未満の利益なら見送り |
| `horizon_days` | 60 | 何日先の権利付最終日まで見るか |
| `popularity_premium` | 高0.5／中0.3／低0 | 先回りの貸株料に、最安時の利益の何割まで使うか |
| `max_lookback_business_days` | 10 | 無期限の一般信用で何営業日前まで先回りを検討するか |
| `dividend_tax_recovered` | true | 株式数比例配分方式＋特定口座での配当受入で、配当の税が戻るなら true |
| `benefit_tax_rate` | 0 | 優待にかかる税率の目安（例 0.3042） |
| `seido_risk_basis` | `worst` | 制度信用を最高料率×4倍の逆日歩で判定するか |
| `exclude_codes` | [] | **勤務先・取引先など売買しない銘柄コード**（入力ミス防止の補助） |
| `include_long_term` | false | 長期保有条件つき銘柄も候補に含めるか |
| `capital_budget_yen` | 0 | 優待クロスに使える資金の上限（円）。0 は上限なし。`--budget` でも指定可 |
| `min_margin_deposit_yen` | 300000 | 信用口座の最低保証金。必要資金の計算に使う |
| `auto_popularity` | true | 「人気」が空欄の銘柄を自動判定するか |
| `rates_checked_on` | 2026-09-30 | 料率を最後に確認した日。90日たつと警告が出る。確認したら更新する |
| `methods` | SBI・楽天・制度 | 証券会社ごとの料率・返済期限・手数料。**最新の料率に更新して使う** |

証券会社を追加したい場合は `methods` に1つ追加します。`max_hold_days` は返済期限の日数、`hold_basis` はその数え方です（`business`＝営業日、`calendar`＝土日祝を含む暦日）：

```json
{"id": "xxx_short", "broker": "XXX", "label": "XXX証券 一般信用(短期)", "kind": "ippan",
 "lending_rate": 0.039, "max_hold_days": 15, "hold_basis": "business", "day_count": "both",
 "commission_buy": 0, "commission_short": 0, "enabled": true}
```

## 5. 毎日の使い方

### 候補とスケジュール

```bash
python -m yutai_cross plan -o mydata/reports
```

出力の見方：

- **今日／次の営業日にやること**：`[エントリー]` `[最終日]` `[短期初日]` `[現渡し]`。発注は講座どおり「①信用売り → ②現物買い（特定）」の順で表示されます
- **条件を満たす候補**：見込み利益の大きい順
  - クロス日：エントリーの目安日
  - どこで：証券会社と信用区分（例：楽天 短期、SBI 無期限）
  - 付最終日：権利付最終日（クロスの締め切り）
  - 利益：優待価値 − 貸株料など（円）
  - 状態：「あと7営業日」＝目安日まであと何営業日か
- **見送り**：利益不足、長期条件、売建不可など
- **注意事項**：全銘柄共通の注意は1行にまとめ、銘柄ごとに直すべき点だけ出します
- **必要資金ピーク**：目安どおりに建てたときに同時に必要なお金の目安

`mydata/reports/` には次のファイルができます：

- `plan_YYYYMMDD.md`：銘柄ごとの詳しい手順（返済期日つき）、コスト内訳、方法別の比較表（建て可能開始日・損益分岐日・目安日）
- `plan_YYYYMMDD.csv`：Excel で開ける一覧
- `yutai_cross.ics`：エントリー目安日・短期初日・権利付最終日・現渡し日のカレンダー。Googleカレンダーなどに読み込めます

建て可能開始日・損益分岐日・目安日が同じ日付なら、「建てられる最初の日に建てても最低利益が残るので、その日を目安にした」という意味です。利益が薄い銘柄では、損益分岐日や目安日が後ろにずれます。

### 資金枠を決める

```bash
python -m yutai_cross plan --budget 1000000
```

資金が限られているときは、使える上限を指定します。ツールは利回り（利益÷必要資金）の高い候補から順に、期間が重なっても上限を超えない組み合わせを選び、収まらない候補は「見送り（資金枠）」にします。必要資金は「現物代金＋委託保証金（建玉の30%、口座全体で最低30万円）」で計算します。毎回指定しないなら、設定の `capital_budget_yen` に書いておきます。

### 今日やることだけ見る

```bash
python -m yutai_cross today
```

やることがない日は、「次の予定」（次にやることがある営業日）を表示します。料率の確認日が古いときや、建玉の記録で対応が必要なもの（返済期日を過ぎている・優待が届いていない）は、最初に「先に確認してください」として表示します。

### 建てた建玉を記録する（position）

クロスしたら記録しておくと、ツールがその建玉に合わせて知らせてくれます。

```bash
# 1. クロスしたら（約定日・単価を入れる。方法は today に出た id）
python -m yutai_cross position add X001 --method rakuten_short --date 2026-10-16 --price 1850
#    → 権利付最終日・現渡し日・返済期日・見込みコストを表示し、mydata/positions.csv に記録

# 2. 権利落ち日に現渡ししたら（1 は add のときに表示された ID）
python -m yutai_cross position close 1 --date 2026-10-29

# 3. 優待が届いたら（評価額＝受け取った時の時価）
python -m yutai_cross position received 1 --value 3000
#    → mydata/executed.csv に1行追記（貸株料・配当は見込み値なので、取引報告書の値で直す）

# 一覧を見る
python -m yutai_cross position list
```

記録があると、`today` は次のように動きます。

- 記録した銘柄のエントリー・最終日の通知を止める（二重に建てない）
- 権利落ち日に「保有中の建玉を現渡し」と、返済期日つきで知らせる
- 返済期日を過ぎても「保有中」のままなら警告する
- 現渡しから時間がたっても優待の記録がなければ、確認を促す
- 記録を使っている間は、見送った銘柄に「現渡し」の通知を出さない

権利付最終日以前の日付で `close` しようとすると、権利がなくなる日付なので止めます（本当にその日に現渡ししたなら `--force`）。

### 1年分のカレンダー

```bash
python -m yutai_cross calendar                 # ウォッチリストの銘柄の権利日（今月から12か月）
python -m yutai_cross calendar --month-end     # 月末権利の一覧
python -m yutai_cross calendar -o mydata/calendar.md
```

権利付最終日・権利落ち日・各社の短期初日を、日付順の表で出します。

### 株価の入れ方

- **おすすめ**：証券会社からダウンロードした「コード,株価」の CSV を `mydata/prices.csv` に保存し、`--prices mydata/prices.csv` で渡す
- 任意：`--fetch-prices` で米Yahoo Finance の非公開APIから取得することもできます。公式に提供されたAPIではなく、利用規約上、自動取得が認められていない可能性があります。使う場合は個人の確認用途に限り、取得したデータは再配布しないでください。取れなかった銘柄はウォッチリストの株価を使います

株価は貸株料の計算に使うだけなので、数%ずれていても判定への影響は小さいです。

## 6. 毎日自動で実行する

### Mac / Linux（cron）

平日20時に「今日と明日やること」をファイルに書き出す例：

```
0 20 * * 1-5 cd /path/to/repo && /usr/bin/python3 -m yutai_cross today > mydata/today.txt 2>&1
```

### Windows（タスクスケジューラ）

1. タスクスケジューラ → 基本タスクの作成 → 毎日 20:00
2. 操作：プログラムの開始
   - プログラム：`cmd`
   - 引数：`/c py -m yutai_cross today > mydata\today.txt 2>&1 && notepad mydata\today.txt`
   - 開始：README.md があるフォルダ

`today --exit-code` にすると、やることがない日は終了コード1になるので、「やることがある日だけ通知する」仕組みも作れます。

### カレンダーに入れる

`plan -o mydata/reports` でできた `yutai_cross.ics` を Googleカレンダーの「インポート」で読み込むと、スマホに予定が出ます（週1回くらい更新して読み込み直す）。

## 7. ツールの判定ロジック（しくみ）

1. **日程計算**：権利確定日 → 実質の確定日（休場なら前営業日）→ 2営業日前が権利付最終日 → 翌営業日が権利落ち日。祝日は祝日法のルールで計算、年末年始（12/31〜1/3）も休場
2. **方法ごとのコスト**：売建方法（証券会社×短期/無期限、制度信用）ごとに、各営業日にクロスした場合の貸株料・逆日歩（想定／最高料率×4倍の見積もり）・手数料・配当まわりのズレを計算
3. **建て可能期間**：一般信用（短期）は、返済期日が権利落ち日以降になる最初の日（短期初日）から。SBI証券は権利落ち日の15営業日前、楽天証券は権利落ち日の13日前（休日なら翌営業日）。無期限は `max_lookback_business_days` まで。制度信用は権利付最終日のみ
4. **損益分岐日**：最低利益を確保できる最も早い日
5. **エントリー目安日**：人気に応じた割合（`popularity_premium`）まで貸株料が増えてもよい範囲で、最も早い日
6. **方法の選び方**：目安日の利益が最も大きい方法（制度信用は初期設定では最高料率×4倍の逆日歩で見た利益で比較）
7. **並べ方**：見込み利益の大きい順

## 8. 困ったとき

| 症状 | 対処 |
|---|---|
| 「No module named yutai_cross」 | README.md があるフォルダで実行していません。フォルダを移動してもう一度 |
| 「ウォッチリストが見つかりません」 | README.md があるフォルダで実行しているか確認。はじめてなら `python -m yutai_cross init` |
| 「株価が未設定のためスキップ」 | ウォッチリストに株価を入れるか `--prices` |
| 「〇行目（Excelの行番号）: 権利月が読めません」 | 権利月は1〜12の数字で。Excel が日付に変えた場合は「3・9」と書き直す |
| 「〇行目: 数字として読めません」 | 優待価値や株価に「相当」などの文字を入れない |
| 「〜を読めません」（一般信用列） | `SBI短期;楽天短期` のように書き直す |
| 「settings.json の〇行目 〇文字目付近…」 | カンマの付け忘れ・余計なカンマを直す |
| 「〜を読み書きできません」 | 出力ファイルを Excel で開いていたら閉じてからもう一度 |
| 「料率を確認した日から〇日たっています」 | 証券会社のサイトで貸株料・手数料・返済期限を確認し、settings.json の methods と `rates_checked_on` を更新 |
| 「〜の建玉が複数あります」 | `position list` で ID を確認し、ID で指定する |
| 「返済期日が権利落ち日より前になります」 | その方法ではその日に建てても権利が取れない。日付か方法（--method）を確認 |
| 全部「見送り」になる | `min_profit_yen` が高すぎないか、優待価値が正しいか確認 |
| 日付が証券会社の表示と違う | 臨時休場などがあれば設定 `extra_market_holidays` に追加。それでも違えば証券会社の表示を優先 |

## 宿題（卒業課題）

1. 自分のウォッチリストを10銘柄作る
2. `plan -o mydata/reports` を実行し、1位の銘柄の Markdown レポートを読む
3. 次の権利月で、在庫を確認して1銘柄クロスしてみる（付録のチェックリストを使って）。建てたら `position add` で記録
4. 現渡ししたら `position close`、優待が届いたら `position received` で記録する

おつかれさまでした！ここまでできれば、優待クロスを自分で回せます。
